# 开发审查与迭代清单

本轮实现记录：一起听改用无房主共享队列，播放栏提供点歌、队列和退出入口；评论区采用连续分页、可定位引用和移动播放页入口；标签编辑区分覆写与文件写入，批量写入前确认文件与字段，保留回退原文件的路径。以下验收项保留，用于核对真实音乐库和多端效果。

本次以工作区源码和[分阶段待办](todo.md)为依据，核对功能、操作者权限、数据一致性及与 Feishin 的界面衔接。第一阶段沿用 2026 年 11 月 7 日的交互验收记录；第二至第六阶段已有实现，均需继续开发或验证。本次结论来自静态审查，交互、手机存储和部署指标以本轮迭代后的验收记录为准。

ServerMan 尚未正式接入，属于预期状态。现阶段在本地账号环境完成业务验收，正式中心登录和账号绑定按原计划单独验证。刮削服务及候选匹配依照[产品设计](design.md#元数据整理)暂缓，待恢复排期后再验收候选预览、字段选择和应用流程。

## 01 基础功能回归

第一阶段交付范围以[开发记录](development.md#已完成的交付)为准。后续修改媒体、播放器或元数据时，以下流程随对应阶段验收。

- [ ] `/music/` 和 `/app/` 保持同源运行，站点前缀下的导航、静态资源及媒体地址正确。曲目、专辑、歌手、搜索、歌单与收藏入口可进入同一套播放流程。
- [ ] 曲目与专辑共享图片内容时，在相同输出规格下共用封面地址；独立曲目封面保留自己的引用。图片更新后返回新版本，旧队列中的可归一化封面仍可跳转。
- [ ] 原始音频可按 Range 读取并拖动进度；播放列表、播放栏、队列和兼容接口继续使用正确曲目及关联信息。专用转码保留原有入口。

## 05 一起听：无房主与独立共享队列

当前原型以服务端房间状态为基础，但客户端每次队列变化都将共享队列载入个人播放器。追加或重排非当前曲目也可能重置正在播放的曲目；播放器重新生成队列项 ID，原有自动切歌和部分本地队列操作仍可单独改变播放。开启恢复队列设置时，共享队列还会进入个人持久化路径。见[房间同步](../web/src/renderer/features/site/room.tsx#L130)、[本地自动切歌](../web/src/renderer/store/player.store.ts#L947)、[载入队列](../web/src/renderer/store/player.store.ts#L1536)和[恢复设置](../web/src/renderer/store/player.store.ts#L1816)。

| 编号 | 开发核对项 |
| --- | --- |
| R1 权限 | 采用无房主的单房间，全员平权。移除房主字段、主持权限、接任分支及相关界面文案。所有已加入成员共享播放、暂停、跳转、切歌和队列操作权限；端点统一校验成员资格与音乐库访问权限。 |
| R2 状态 | 个人队列与共享队列分别保存；共享状态包含会话标识、队列项 ID、当前项、播放状态、进度基准和状态版本。复用音频引擎，按当前模式路由播放器操作；本地音量和静音由设备自行控制。正常退出、断网退出及刷新走同一套个人播放恢复规则。 |
| R3 队列 | 提供独立队列页或面板，支持站内搜索点歌、从曲目菜单加入、插入下一首、跳到指定项、拖动或键盘排序和移除。显示封面、曲目、可跳转歌手、点歌人及当前播放标识。重复曲目保留独立队列项；修改非当前项时当前音频和进度保持连续。 |
| R4 协作 | 服务端按统一顺序执行命令。排序、移除和选择使用队列项 ID，可能覆盖其他编辑的操作校验状态版本；冲突时返回新状态并让用户继续操作。约定当前项被移除、队列见底、无人在线以及不同音乐库权限时的行为，界面给出与结果一致的反馈。 |
| R5 时钟 | 服务端负责自然切歌，客户端根据服务时间跟随进度，避免本地自动切歌和跨曲淡入淡出提前推进共享队列。稳定状态仅校时，切歌时准备新音频。按设备恢复心跳与加入状态；同账号其他设备仍在线时，本设备仍可重连。进程重启后以新会话空闲状态为准。 |

原型目前以用户是否在线决定设备重加，并仅用递增序号过滤旧状态；同账号多设备和服务器重启是两条独立的恢复路径。退出动作先等待网络请求成功，断网时应先恢复本地个人模式。见[离开流程](../web/src/renderer/features/site/room.tsx#L54)、[重连判断](../web/src/renderer/features/site/room.tsx#L115)与[服务端时钟](../backend/server/site_room.go#L43)。

- [ ] 两个账号均可控制共享播放；任一位成员离开后，另一位立即继续操作。房间操作与页面中均无房主状态。
- [ ] 将同一首歌添加两次，分别排序、播放和移除；两台设备上的当前项一致。并发追加或排序不会覆盖已确认操作，追加及重排非当前项不会重播当前曲目。
- [ ] 覆盖同一账号多设备、失网重连、后台返回、刷新、离线退出和服务重启。加入前的个人队列、当前项、进度、顺序及随机和循环设置可恢复。
- [ ] 双端核对播放、暂停、切歌、拖动和自然切歌；记录稳定网络下的实际播放进度差，目标为 500 毫秒。

| 编号 | 发现与影响 | 开发核对项 |

| O1 | 更新失败可恢复旧条目，但页面仍可能清除更新提示；成功替换后，按曲目 ID 复用的 Blob URL 可能继续指向旧文件。见[本地播放](../web/src/renderer/features/site/offline.ts#L117)、[下载收尾](../web/src/renderer/features/site/offline.ts#L192)与[更新入口](../web/src/renderer/features/site/offline-page.tsx#L125)。 | 新文件与目录成功写入后再切换版本，更新播放器引用；失败或取消时继续提供旧版本与重试提示。识别资源更新、设备文件丢失、空间不足和网络中断。 |

| O3 | 离线启动依赖浏览器联网标志；设备有网络但服务端不可达时可能转入普通网络错误页。退出与账号切换涉及查询、下载任务、封面和播放器引用，应统一按账号处理。见[离线启动](../web/src/renderer/hooks/use-server-authenticated.ts#L54)与[退出动作](../web/src/renderer/store/auth.store.ts#L52)。 | 对有本地目录的账号提供一致的离线入口。退出先解除旧账号的播放和缓存引用，按选项保留或删除下载。下载中切换账号时，任务、错误和目录仍归原账号；新账号只显示自己的条目。 |

## 07 界面与交互

以 Feishin 的导航、页头、列表、播放器和主题为界面基准。主流音乐软件和音乐社区用于对标任务完成度：点歌、离线管理、歌词和讨论都能在对应页面完成，反馈能说明结果与下一步。新增页面已使用部分共享组件与主题变量，但[通用面板样式](../web/src/renderer/features/site/site.module.css#L15)和[曲目详情](../web/src/renderer/features/site/track-page.tsx#L29)与[原生专辑详情](../web/src/renderer/features/albums/routes/album-detail-route.tsx#L60)的内容层级及控件布局不同。建议优先复用原生页面结构和组件，再为各功能设计专有内容。

| 区域 | 开发核对项 |
| --- | --- |
| 导航与账号 | 桌面和手机使用一致的入口归类、图标和选中态。一起听保留独立入口，离线音乐归入音乐库，账号和隐私归入个人菜单或设置。 |
| 曲目与播放 | 沿用 `LibraryHeaderBar` 和原生详情页模式。显示封面、标题、歌手、专辑及主要播放操作，次要操作进入菜单。列表、详情、桌面与移动播放栏、共享队列使用同一套歌手链接规则。手机播放页可直接进入歌词、队列和讨论。 |
| 一起听 | 当前播放、下一首、点歌为首要内容；成员及设备状态放在次级区域。桌面可并排显示播放信息与共享队列，手机使用便于返回的队列面板。迷你播放栏显示当前模式，加载、重连或暂停状态清晰可见。 |
| 讨论与资料 | 以作者、发布时间、正文、回复关系和播放时间构成阅读顺序；点赞、回复等高频操作直接可达，管理操作纳入菜单。公开资料按曲目、专辑、歌手复用原生列表。 |
| 离线与编辑 | 离线页以专辑、曲目、状态和进度为主，用行菜单收纳取消、重试和删除。用站内统一确认框处理批量清理和退出。元数据表单突出改动、来源、预览与保存结果，文件写入前说明受影响范围。 |
| 全部页面 | 复用共享图标、菜单、提示、加载及错误状态，跨浅色、深色与自定义主题核对颜色。窄屏长标题、长歌手名和按钮组有明确的省略或换行方式；主要操作可用键盘完成，图标按钮有可读名称。已支持界面的文案走现有 i18n。 |

## 08 实施顺序与完成记录

1. **先确定状态和数据边界。** 优先落实 R1、R2、R4、R5，明确两套队列和设备生命周期；同轮处理 D1、D2、D5、M1、M2、O1、O3。上述问题直接影响播放同步、文件完整性、凭据和账号数据。
2. **再完成日常操作和界面。** 以独立共享队列为中心完成点歌、排序和播放控制，完成移动讨论、公开资料、下载管理与元数据表单；按第 07 节统一原生组件和移动交互。
3. **最后按交付流程统一验收。** 用同一份音乐库、两个有明确权限的本地账号和目标手机覆盖各节清单。媒体上线另用部署环境记录 CDN 结果；ServerMan 正式接入时单独核对会话与账号绑定。将验收对象、环境、实际结果和待处理项写入[开发记录](development.md)，对应条目验证通过后再更新[分阶段待办](todo.md)。
